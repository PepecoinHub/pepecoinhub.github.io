# A14 Pond Case Files: review and rollout gates

This is a draft feature, not a production runbook authorization. Do not add it to LAUNCH_ALL or execute it on production without explicit approval. Never commit the actual campaign JSON, generated seed SQL, answers, hashes, future clue text, or founder correspondence.

## Independent review (disposable environment only)

1. Review `../update_pond_case_files.sql` against the deployed Passport schema, gate and Discord identity helper. Confirm `pond_case_private` is absent from the Data API exposed schemas and its definer functions have the intended owner, fixed search path, and explicit ACLs. No public/anon execution or direct table access; authenticated users can execute only the two owner-bound endpoints and their necessary internal delegates. No client-provided account ID is accepted. Verify any existing Passport award restrictions and that the legacy generic discovery RPC cannot award the new secret ID.
2. Run `node --test tests/*.test.mjs`. In a separate expendable local database, run the SQL integration fixture with `PASSPORT_PG_URL` and `PASSPORT_PG_MODULE` pointing to an available node-postgres installation. The fixture creates/removes test schemas; never point it at production or a shared database. Review actual role ACLs, concurrent answers, stale stage protection, duplicate final submissions, and transaction rollback on failure.
3. Use synthetic seed content to exercise desktop and mobile: no campaign, sign-out, correct/wrong answers, hint, cooldown, account switching during a delayed response, browser reload, and final message plus Passport refresh. Verify that hidden future clues, answer hashes and other users' state are absent from all responses. Verify no answer bodies are retained by debug logs/analytics. Test mobile input and keyboard, dark/light appearance, and closed dialog behavior.
4. Test the existing companion and legacy secret paths; sandbox must not read or write a real campaign. A new quest must never change care, pet rewards, game scores, or financial balances.

## Private content and actual launch (separate approval required)

- Obtain the genuine founder message, consent to release it through the quest, and an accurate attribution. Curator reviews all six clues and mobile equivalents independently; do not include sensitive personal information. The private file intentionally omits the founder text until supplied.
- Generate a disabled seed from the private curator JSON using `node scripts/build_pond_case_sql.mjs /path/to/private.json`. The script writes an ignored private SQL file, never connects to a database, and rejects replacing a played or enabled campaign. Keep that file out of repo, previews, CI logs, public SQL editors and collaboration attachments. Never store plaintext answers in the DB. Keep actual seed content accessible only to the authorized operator.
- After independent review and explicit owner approval, the authorized operator can apply the empty migration in the agreed release order, seed privately, inspect config without exposing content, and enable only after the real message and attribution are present. The engine additionally checks that stages are contiguous and Passport is open. Verify permissions before enabling the feature. Activation is reversible by disabling the campaign; do not reset player progress or replace a played case. There is no automatic production activation.
